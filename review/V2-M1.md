## 3. Findings

### MAJOR-1: the html-validate gate fails (2774 errors)

The SPEC says "KEEP: html-validate". `npx html-validate@8.18.2 "dist/**/*.html"` uses the default `recommended` preset (the repo has no `.htmlvalidate.json`) and exits 1.

- **`tel-non-breaking`** fires 2507 times on every page. Spaces inside `<a href="tel:…">` link text trigger it. That covers both the number and the label space in «Позвонить: 8 706…». The sources are:
  - `src/lib/layout.js:15`: `${esc(t.call)}: ${esc(config.phoneDisplay)}`
  - `src/lib/layout.js:96` (footer)
  - `src/pages/static.js:109` (contacts)

  This is a real UX issue too: the number can wrap mid-number.

  **Fix:** add a helper `const telText = (s) => esc(s).replace(/ /g, '&nbsp;')` and use it for the phone text in all three places. In layout.js:15, join the label with `&nbsp;` as well (`${esc(t.call)}:&nbsp;${telText(config.phoneDisplay)}`), or move the label outside the `<a>`. Do not change `config.phoneDisplay` itself, because it is also used in meta descriptions.
- **`doctype-style`** fires 267 times. **Fix:** in `src/lib/layout.js:118`, change `<!doctype html>` to `<!DOCTYPE html>`, and do the same for any other page that writes its own doctype.
- **Also:** add the html-validate run to `scripts/check.js` (or to `npm run check`) so the gate cannot regress silently.

### MAJOR-2: city pages pass the duplicate check only because of the shuffle (gaming)

DECISIONS.md:84 says category order and product order in the full-catalog block are shuffled per city "without both, the shared catalog text pushed city pages above Jaccard 0.70". I rebuilt a copy in the scratchpad with the shuffle removed (`pickMany` replaced with the plain order in `src/pages/city.js:26-27`) and reran `jaccard_v2.mjs`:

| variant | ≥0.70 | ≥0.60 | max |
|---|---|---|---|
| as committed (shuffled) | 0 | 1 | 0.636 |
| same content, canonical order | **4** | 21 | **0.796** (`/goroda/aktobe/` vs `/goroda/zhezkazgan/`, kk 0.792); `konaev`/`turkestan` 0.730/0.720 |
| catalog block removed entirely | 0 | 2 | 0.658 (`aktobe`/`zhezkazgan`) |

The shuffle adds no information. Each page shows the same 59 links, only reordered, and the reordering also hurts usability: the categories appear in a random order. It lowers a word-shingle metric without making the pages less similar for a reader or a search engine. That is **gaming the check**.

There are two real causes:
1. **`aktobe` and `zhezkazgan` have the identical `productFocus` set** (`src/data/cities.js`; the same 6 slugs in a different order). Several other pairs share 4-5 of 6, for example konaev/turkestan and atyrau/pavlodar.
2. **The "focus" block reuses each product's generic `description[lang]`** verbatim (`src/pages/city.js:33`). DECISIONS.md:76 promises "6 recommended products from `productFocus` with a city-specific reason", but no city-specific reason exists anywhere. So the only city-specific text is `context` (2 sentences) plus the sectors list; the rest is template text plus the city name.

**Fix (substantive):**
1. Render the full catalog in canonical category and product order, and drop `pickMany` in city.js:26-27. It is navigation, so keep it compact and consistent.
2. Add `focusWhy: { [slug]: { ru, kk } }` to each city in `cities.js`. Write one concrete sentence per focus product tied to that city's economy, for example for Zhezkazgan / `crm-dlya-malogo-biznesa`: «Подрядчикам горно-обогатительных предприятий важно не терять заявки на ремонт техники между сменами». Render that sentence plus the price instead of `p.description`. The full description belongs on the product page.
3. Make `productFocus` distinct, with no two cities sharing more than 3 of 6. aktobe and zhezkazgan must differ (for example Zhezkazgan: copper/mining services, so `otchety-v-telegram`, `zayavki-v-google-sheets`, `kompyuternaya-gramotnost`).
4. Make the city FAQ answer #2 use `focusWhy` text instead of only listing titles.
5. Rerun `jaccard_v2.mjs` with no shuffle. The target is < 0.60 for all city pairs.
